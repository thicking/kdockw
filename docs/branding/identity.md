# KDockW project identity

## Official name

Use **KDockW** for the application and project in current user-facing text. The
name expands to **KDE Dock for Wayland**. Use this exact expansion at the top
of the README and on first mention in external descriptions. Keep the casing
KDockW; do not write Kdockw, KDockw, or KREMA as the current product name.

Use **KDockW** for the executable, XDG autostart examples, and current product
references. Technical identifiers retain their defined lowercase or reverse
DNS spelling, including kdockw, kdockwrc, com.thicking.kdockw, and
com.thicking.kdockw QML imports. Legacy user-created unit names belong only in
manual migration instructions or historical records.

## Repository and links

The canonical source repository, issue tracker, homepage, and contribution
entry point are:

- Repository: <https://github.com/thicking/kdockw>
- Issues: <https://github.com/thicking/kdockw/issues>
- Build and contribution instructions: [README](../../README.md)

Current source, packaging, application metadata, and website links must use the
canonical KDockW repository. Historical packaging recipes may retain a
repository URL only when it is part of a verified, checksummed source pin; mark
that provenance clearly and do not mistake it for the current source address.
The deployed website path follows the repository name:
<https://thicking.github.io/kdockw/>.

## Origin and attribution

KDockW is developed independently from the original [Krema
project](https://github.com/isac322/krema), originally created by Byeonghoon
Yoo. Preserve that attribution, upstream copyright notices, retained Git
authorship, and the license notices required by GPL-3.0-or-later and third-party
components. Mention Krema when describing project origin, migration, historical
releases, or inherited assets. Do not present Krema as KDockW's current name,
repository, or automatic upstream.

Old repository paths, package-channel identifiers, app IDs, and configuration
names belong in migration instructions and historical records where they
identify the exact legacy resource. Do not globally replace those identifiers.
The former repository path thicking/krema is historical; current KDockW URLs
use thicking/kdockw. For publishing targets, use a public/API-verified KDockW
owner and project; never infer a third-party owner's identity from an old
resource or from the GitHub login.
